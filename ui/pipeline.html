The one law

Apps talk to Loco; Loco talks to models; nothing else exists. No app configures or fights an inference server — ever. Tools & MCP live in a separate plane on top of external agents, never inside the model router.

Tools & MCP — separate plane, on purpose

┌─ model plane (Loco :8200) ─────────────────────────────┐
│  routes only · never executes tools · never touches net │
│  local GGUF stack / managed backend pass `tools` through untouched      │
└───────────────┬────────────────────────────────────────┘
                ▼
┌─ agent plane (your agents) ─────────────────────────────┐
│  tools · MCP servers · skills · planning loop          │
│  tool_choice enforcement lives HERE, not in the router │
└────────────────────────────────────────────────────────┘

this is the whole point of “support agentic workflows”: Loco guarantees any agent any brain, deterministically, without bargaining with an inference stack. Agents wire MCP on top; Loco stays a clean, dumb, fast traffic cop.

Eval loop — how the router gets smarter

  1. every route → route_log (task, model, backend, tokens, latency, cache_hit, gpu_mib_before)
  2. shadow eval reads it → p50/p95 latency, cache-hit rate, degradation rate, per-task success proxy
  3. weights in loco/routing.py (TASK_MODEL, cache gate) tuned from data — never vibes
  4. monthly: nightly consolidation writes an episodic→semantic distillation; promotion only via eval delta
